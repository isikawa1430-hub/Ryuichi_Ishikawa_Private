## 2. 現状診断：なぜ今変える必要があるか

「利益が出ない」は結果であって、原因ではない。
**本質は「稼がなくていい文化が、5年かけて組織に定着してしまった」こと。**

### 問題の連鎖構造

```
梓設計主宰が方向性を示さない・言及しない
        │
        ▼
「親会社のイメージアップが自分たちの仕事」という空気が主流になる
        │
        ▼
社長がプレッシャーなくやりたいことを進める
        │（イグジット基準がない・プロジェクトが終わらない）
        ▼
利益を出す議論が封じられる ＋ 取締役が状況を聞くだけで機能しない
        │
        ▼
社長が全プロジェクトを一人で抱え、5年目でも独立採算の意識がない
```

### 主要プレイヤーの実態

| プレイヤー | 現状 | 変革における関わり方 |
|---|---|---|
| 梓設計主宰 | 年1回の発表イベント参加のみ。社員と交流なし | 四半期ごとの事業報告・対話の場に変える |
| 梓総研社長 | プレッシャーに弱く、事業イグジット判断が甘い。全PJを一人で抱える | 潰さず変える。収益・イグジット判断を石川が補完 |
| 現取締役（本社降下） | 各プロジェクトに紐づかず、会議で状況を聞くだけ | 担当事業領域を持たせ、意思決定責任者に変える |
| 若い取締役 | バックオフィスの雑務に注力。取締役の本来機能を理解していない | 「戦略的経営管理者」の役割に引き上げる |
| 梓総研社員 | 「好きな研究をする場所」という認識が定着 | 「好き×社会が求める役割」の自覚を持たせる |

### Before / After

| 軸 | Before（現在） | After（目指す梓総研） |

### 変革の5本柱

**柱1：「稼ぐことを義務にする」文化の宣言**

収益目標を全社員の前で宣言し、各プロジェクトに「事業貢献度」の評価軸を加える。社長の「やりたいこと」と「会社が求めること」を分離して管理する仕組みを作る。

社長との関係設計：対立ではなく補完。社長は「研究の質・対外関係・詳細品質」を担い、石川さんは「事業化・収益・イグジット判断」を担う。

---

**柱2：研究と事業を仕分ける**

| 象限 | 分類 | 配分・方針 |
|---|---|---|
| 研究性高 × 事業性高 | 戦略的育成 | 全体の30%まで。期限と事業化マイルストーンを設定 |
| 研究性低 × 事業性高 | **主力事業** | 全体の50%。AIR-Plate等。最優先でリソース投入 |
| 研究性高 × 事業性低 | 様子見 | 全体の15%以内。半年でレビュー・撤退判断 |
| 研究性低 × 事業性低 | **即撤退** | 社長の「やりたいこと」でもここに入れば終了 |

プロジェクトイグジット基準：半年でマイルストーン未達 → 自動レビュー。1年で事業貢献ゼロ → 原則終了。例外は取締役会の審議・承認が必要。

---

**柱3：「好き×社会が求める役割」を社員が認知する**

「技術を教える」ではなく「自分で考えて事業を動かせる人間を作る」こと。AIが多くの作業を代替する時代に、「AIを使って価値を作れる人」を育てることが最大の育成テーマ。

---

**柱4：梓設計社員が「数年勤めたい」と思う場所にする**

「梓総研で働くと何を学べるか」を明確にし、AIを使った高効率・高付加価値な働き方を体験できる場にする。梓設計主宰との関係を年1回の発表会から四半期の事業対話に変える。

---

**柱5：「AIが回す20人規模の会社」を実現する**

| 業務領域 | 現状 | AI化後 |
|---|---|---|
| 提案書・報告書作成 | 人が書く | AIが下書き、人が確認・判断 |
| 議事録・ナレッジ整理 | 放置または手動 | 自動記録・自動整理 |
| プロジェクト進捗管理 | 口頭・Excel | AI自動集計・アラート |
| 営業パイプライン管理 | 属人的 | AI予測・優先度付け |
| 採用・人事評価 | 感覚的 | データドリブン＋AI補助 |

梓総研が「AIが回る組織の実証実験場」になることで、梓設計への「逆輸入」が生まれる。これが親会社への本来の貢献。

---

### ガバナンス改革：取締役の役割を再定義する

**原則：取締役は「状況聴取者」ではなく「意思決定者・事業責任者」**

| 役割 | 現状 | 変革後 |
|---|---|---|
| 本社からの取締役 | 会議で状況を聞く | 担当事業領域を持ち、P/L責任を持つ |
| 若い取締役（バックオフィス） | 総務・経理の雑務 | 予算・採用・AI化の戦略設計者 |
| 社長 | 全プロジェクトを一人で抱える | 対外・研究品質・全体ビジョンに集中 |
| **石川さん（新取締役）** | AIR-Plate事業の実質担当 | **事業収益・新事業・組織変革の責任者** |

4つの具体的改革：
1. 各取締役に担当事業領域を割り当てる（石川さん→事業収益、バックオフィス→経営管理）
2. バックオフィス取締役を予算・採用・AI化推進の戦略設計者に引き上げる
3. 社長からプロジェクト所有権を段階的に分散させる（石川担当分から先行）
4. 取締役会を「状況報告の場」から「意思決定の場」に変える

就任時に宣言すること：「私が担当する事業領域については、私が意思決定します。社長には重要事項のみ報告します。」

## 6. 事業間シナジーの深掘り戦略

> 3事業が別々に動けば「3つの事業」だが、シナジーを設計すれば「誰にも真似できないエコシステム」になる。

### シナジーの全体構造

```
【公的権威の基盤】
  国土交通省BIM政策  ×  芝浦工大WG
            │
            ▼
  ┌──────────────────────────────────┐
  │   BIM属性管理プラットフォーム     │ ← 「標準」を握る
  │   （業界のルールを作る側）         │
  └──────────┬───────────────────────┘
             │標準定義が教材になる    │標準準拠を求める企業が顧客に
             ▼                        ▼
  ┌──────────────────┐    ┌──────────────────────┐
  │  AIコンサルティング  │◄──►│      AIR-Plate         │
  │  （知識を外販する）  │    │（標準の実装リファレンス）│
  └──────────────────┘    └──────────────────────┘
             └─────────────────────────┘
                       ▼
             【データ資産】建築AIデータセット
             （他社が持てない知的インフラ）→ 2027年10月 起業の基盤
```

### 6つのシナジー提案

**提案1：標準化プレミアム戦略**
BIM標準を握った瞬間、AIR-Plateは「標準の実装リファレンス」に昇格する。競合が価格で戦えない世界になる。
→ AIR-Plateの「BIM標準準拠」機能マッピングを開始し、芝浦工大WGで研究テーマとして提案する。

**提案2：コンソーシアム＝顧客獲得エンジン**
コンソーシアム参加企業は標準化対応を迫られる。その「対応支援」がAIコンサルの自然な受注につながる。顧客獲得コストゼロの営業組織として機能させる。
→ コンソーシアム招待リストをAIコンサルのターゲット企業リストと重ねて設計する。

**提案3：データフライホイール**
AIR-Plate（業務データ）× AIコンサル（活用知見）× BIMプラットフォーム（標準属性定義）= 他社が持てない「建築AIデータセット」。将来の最大の参入障壁になる。

**提案4：建築DX道場（人材エコシステム）**
AXタスクフォース → AIR-Plate実践 → AIコンサル外販 → BIM標準化参画 という成長パスを設計。石川さんが「館長」として業界全体に影響力を持つ。

**提案5：公的権威×民間実装の差別化**
芝浦工大WG・国交省連携という「公的正当性」は民間企業が複製できない優位性。AIR-Plate・AIコンサルの差別化として積極的に使い切る。

**提案6：エコシステムごと起業に持ち出す設計**
梓総研取締役（信用）× 個人会社（機動力）の二重構造。「この人なしには動かない」ポジションを今から設計する。AIコンサルのブランド帰属・商標を法務的に確認しておく。
