## 2. 現状診断：なぜ今変える必要があるか

「利益が出ない」は結果であって、原因ではない。
**本質は「稼がなくていい文化が、5年かけて組織に定着してしまった」こと。**

### 問題の連鎖構造

```
梓設計主宰が方向性を示さない・言及しない
        │
        ▼
「親会社のイメージアップが自分たちの仕事」という空気が主流になる
        │
        ▼
社長がプレッシャーなくやりたいことを進める
        │（イグジット基準がない・プロジェクトが終わらない）
        ▼
利益を出す議論が封じられる ＋ 取締役が状況を聞くだけで機能しない
        │
        ▼
社長が全プロジェクトを一人で抱え、5年目でも独立採算の意識がない
```

### 主要プレイヤーの実態

| プレイヤー | 現状 | 変革における関わり方 |
|---|---|---|
| 梓設計主宰 | 年1回の発表イベントに参加するが社員と交流なし。「すごいことをしているアピール」の承認者 | 四半期ごとの事業報告・対話の場に変える |
| 梓総研社長 | 細部への配慮はあるが全体像を見失う時がある。プレッシャーに弱く、事業イグジット判断が甘い | 潰さず変える。苦手な「収益・イグジット」を石川が補完 |
| 現取締役（本社降下） | 各プロジェクトに紐づかず、会議で状況を聞くだけ | 担当事業領域を持たせ、意思決定責任者に変える |
| 若い取締役 | バックオフィス（総務・経理）の雑務に注力。取締役としての本来機能を理解していない | 「戦略的経営管理者」の役割に引き上げる |
| 梓総研社員 | 「好きな研究をする場所」という認識が定着。事業性を意識するインセンティブがない | 「好き×社会が求める役割」の自覚を持たせる |

## 3. 取締役就任後のビジョン：梓総研をどう変えるか

### Before / After

| 軸 | Before（現在） | After（目指す梓総研） |
|---|---|---|
| 存在目的 | 親会社のPR機関 | 独立採算の事業会社 |
| 収益観 | 研究＝善、利益＝後回し | 研究していい、でも稼ぐことも義務 |
| 社員の意識 | 「好きなことをやる場所」 | 事業性と自分の役割を自覚して動く |
| 取締役の機能 | 状況を聞くだけ・雑務担当 | 担当事業を持ち、意思決定責任を持つ |
| 組織規模感 | 20人規模だが従来型運営 | 20人でAIを活用し60人分の価値を生む |
| 梓設計との関係 | 年1回の発表会のみ | 数年勤めたいと思う場所。四半期対話 |

### 変革の5本柱

**柱1：「稼ぐことを義務にする」文化の宣言**

取締役として最初にやること。収益目標を全社員の前で宣言し、各プロジェクトに「事業貢献度」の評価軸を加える。

- 年度ごとの収益目標を全社員の前で設定・公開する
- プロジェクトの「事業貢献度」を評価軸として全員が使う言語にする
- 社長の「やりたいこと」と「会社が求めること」を分離して管理する仕組みを作る

**社長との関係設計**：対立ではなく補完。社長は「研究の質・対外関係・詳細品質」を担い、石川さんは「事業化・収益・イグジット判断」を担う。社長が苦手な領域を引き受けるパートナーとして提示する。

---

**柱2：研究と事業を仕分ける**

「研究していい」が「何でもやっていい」になっているのが現状。全活動を4象限で仕分けし、リソース配分に明確なルールを設ける。

```
              事業性 高
                  │
  研究性 高  ────┼──── 研究性 低
  （育てる）      │      （すぐ刈り取る）
                  │
              事業性 低
```

| 象限 | 分類 | 配分・方針 |
|---|---|---|
| 研究性高 × 事業性高 | 戦略的育成 | 全体の30%まで。期限と事業化マイルストーンを設定 |
| 研究性低 × 事業性高 | **主力事業** | 全体の50%。AIR-Plate等。最優先でリソース投入 |
| 研究性高 × 事業性低 | 様子見 | 全体の15%以内。半年でレビュー・撤退判断 |
| 研究性低 × 事業性低 | **即撤退** | 社長の「やりたいこと」でもここに入れば終了 |

**プロジェクトイグジット基準（明文化する）**
- 半年でマイルストーン未達 → 自動レビュー
- 1年で事業貢献ゼロ → 原則終了
- 例外は取締役会の審議・承認が必要

---

**柱3：「好き×社会が求める役割」を社員が認知する**

自分の強みが社会（市場）でどう役立つかを自覚できる組織にする。「技術を教える」ではなく「自分で考えて事業を動かせる人間を作る」こと。

- 年に1〜2回、個人と組織の「強み×市場ニーズ」をすり合わせる1on1を実施
- 「自分のこの仕事は、誰のどんな問題を解決しているか」を言える状態を目標にする
- AIが多くの作業を代替する時代に、「AIを使って価値を作れる人」を育てることが最大の育成テーマ

---

**柱4：梓設計社員が「数年勤めたい」と思う場所にする**

今、梓設計社員にとって梓総研は「よくわからない研究子会社」にすぎない。これを変えることが、梓設計主宰の当事者意識を変える最も現実的な方法でもある。

実現のための条件：
- 「梓総研で働くと何を学べるか」が明確になっている
- 梓設計と同等以上の待遇（または成果連動の収入機会）がある
- AIを使った高効率・高付加価値な働き方が体験できる
- 戻った後のキャリアに価値がある（「梓総研経験者」というブランド）

**梓設計主宰との関係再設計**：年1回の発表会 →「四半期に1回の事業報告・対話」へ。「すごいことをしているアピール」ではなく「これだけ稼いだ・これが来期の戦略」を話す場に変える。

---

**柱5：「AIが回す20人規模の会社」を実現する**

梓設計（大規模）では実現できない。だから梓総研（20人規模）でやる。これが梓総研の存在意義そのものになる。

```
【従来の20人会社】
ルーティン・書類・分析・レポート → 人間が工数の大半を使う

【目指す梓総研】
ルーティン・書類・分析・レポート → AIが担う
人間がやること → 意思決定・関係構築・創造・例外処理
結果：20人で60人分の売上・付加価値を生み出す
```

| 業務領域 | 現状 | AI化後 |
|---|---|---|
| 提案書・報告書作成 | 人が書く | AIが下書き、人が確認・判断 |
| 議事録・ナレッジ整理 | 放置または手動 | 自動記録・自動整理 |
| プロジェクト進捗管理 | 口頭・Excel | AI自動集計・アラート |
| 営業パイプライン管理 | 属人的 | AI予測・優先度付け |
| 採用・人事評価 | 感覚的 | データドリブン＋AI補助 |

梓総研が「AIが回る組織の実証実験場」になり、梓設計が学べないことを先行実装する。これが「親会社への貢献」の本来のあり方。

### ガバナンス改革：取締役の役割を再定義する

**原則：取締役は「状況聴取者」ではなく「意思決定者・事業責任者」**

| 役割 | 現状 | 変革後 |
|---|---|---|
| 本社からの取締役 | 会議で状況を聞く | 担当事業領域を持ち、P/L責任を持つ |
| 若い取締役（バックオフィス） | 総務・経理の雑務 | 予算・採用・AI化の戦略設計者 |
| 社長 | 全プロジェクトを一人で抱える | 対外・研究品質・全体ビジョンに集中 |
| **石川さん（新取締役）** | AIR-Plate事業の実質担当 | **事業収益・新事業・組織変革の責任者** |

**4つの具体的改革**

①**各取締役に担当事業領域を割り当てる**
```
取締役A（石川さん）     → 事業収益領域（AIR-Plate・AIコンサル・BIMプラットフォーム）
取締役B（バックオフィス）→ 経営管理領域（予算・人事・法務・IT基盤）
社長                    → 研究品質・対外ブランド・組織ビジョン
```
「担当領域内の意思決定は取締役が行う」を明文化。社長への決裁は例外にする。

②**バックオフィス取締役の役割を引き上げる**  
雑務担当から、予算配分の設計・採用制度の設計・AI化推進管理・法務戦略へ転換させる。これにより石川さんが事業側に集中できる体制が整う。

③**社長からプロジェクト所有権を分散させる**  
各プロジェクトにオーナー（取締役または上級社員）を任命し、進捗・収益・イグジット判断の責任を持たせる。社長は「承認者」に徹する。

```
Step 1: 石川さんが担当事業（AIR-Plate等）のオーナーとして完全独立運営
        （就任前から既に実態として近い状態を作っておく）
Step 2: 就任後、他の社員・取締役にもオーナーシップを順次移譲
Step 3: 社長の「自分のプロジェクト」に共同オーナー制を提案し、徐々に分離
```

④**取締役会を「状況報告の場」から「意思決定の場」に変える**  
議題は「報告」ではなく「決議事項」として持ち込む。各取締役が担当領域の数字を持参し、説明責任を果たす。決定事項は必ず議事録に残す。

**就任時に宣言すること**：「私が担当する事業領域については、私が意思決定します。社長には重要事項のみ報告します。」→これを就任条件の一つとして明示する。

---

### 変革の3ステージ

| ステージ | タイミング | やること |
|---|---|---|
| **ステージA（就任前）** | 〜2027年3月 | AIR-Plate売上で「稼げる」を証明。研究と事業の仕分けを自分の担当範囲で試行。社員1〜2名の意識変革を見せる |
| **ステージB（就任交渉時）** | 2027年1〜3月 | 「自分が取締役になったらこう変える」を1枚で提示。社長には補完関係として提示。主宰には「梓総研が稼げる組織になる」リターンで語る |
| **ステージC（就任後100日）** | 2027年4〜7月 | 収益目標を全社に宣言。イグジット基準を明文化・導入。AI化を1〜2プロセスで実施。主宰との定期対話を設定。取締役の役割を再割当て |

## 6. 事業間シナジーの深掘り戦略

> **核心の問い**：3事業が別々に動けば「3つの事業」だが、シナジーを設計すれば「誰にも真似できないエコシステム」になる。

### シナジーの全体構造

```
【公的権威の基盤】
  国土交通省BIM政策  ×  芝浦工大WG
            │
            ▼
  ┌──────────────────────────────────┐
  │   BIM属性管理プラットフォーム     │  ← 「標準」を握る
  │   （業界のルールを作る側）         │
  └──────────┬───────────────────────┘
             │標準定義が               │標準準拠を
             │コンサルの教材になる     │求める企業が顧客になる
             ▼                         ▼
  ┌──────────────────┐    ┌──────────────────────┐
  │  AIコンサルティング  │◄──►│      AIR-Plate         │
  │  （知識を外販する）  │    │（標準の実装リファレンス）│
  └──────────────────┘    └──────────────────────┘
             │                         │
             └─────────┬──────────────┘
                       ▼
             【データ資産】建築AIデータセット
             （他社が持てない知的インフラ）
                       │
                       ▼
             【2027年10月 起業】
             梓総研取締役 × 個人会社代表
             という唯一無二のポジション
```

---

### 提案1：「標準化プレミアム」戦略

BIM属性管理プラットフォームで「業界標準」を握った瞬間、AIR-Plateは単なる製品から「標準の実装リファレンス」に昇格する。競合が価格で戦えない世界を作る。

```
国交省の属性情報リスト
        │（梓総研が管理・更新を担う）
        ▼
  BIM標準属性データベース
        │（「この標準に準拠した唯一のツール」として）
     AIR-Plate
        │（「標準化対応できていますか？」という問いかけで）
    AIコンサル受注
```

- 標準は一度決まると変えにくく、先行者優位が長期間持続する
- 国交省・大学との連携という「公的正当性」は民間企業が簡単に複製できない

**アクション**
- [ ] AIR-Plateが「BIM標準準拠ツール」として位置づけられる準備を開始（機能マッピング）
- [ ] 芝浦工大WGで「AIR-Plateと標準属性の連携」を研究テーマとして提案
- [ ] 「標準準拠ツールとしてのAIR-Plate」を訴求する営業資料を作成

---

### 提案2：「コンソーシアム＝顧客獲得エンジン」設計

BIMコンソーシアム参加企業は標準化への対応を迫られる。その「対応支援」がAIコンサルの自然な受注につながる。コンソーシアムは顧客獲得コストゼロの営業組織として機能する。

```
BIMコンソーシアムへの参加招待
        ↓（「業界標準を一緒に作りましょう」）
標準化への対応が必要になる
        ↓（「自社の設計・製品情報をBIM標準に合わせるには？」）
AIコンサルを受注
        ↓（「梓総研に任せれば標準準拠できる」）
AIR-Plateを導入
        ↓（「このツールで標準化運用を継続できる」）
長期的なプラットフォーム利用者に（解約しにくいロックイン）
```

**アクション**
- [ ] コンソーシアムへの招待リストをAIコンサルのターゲット企業リストと重ねて作成
- [ ] コンソーシアム参加企業向けの「標準化準拠チェックリスト」をAIコンサルのフロントエンド商品として設計

---

### 提案3：データフライホイール（建築AIデータ資産の独占）

3事業のデータを組み合わせると、他社が持てない「建築AIデータセット」が生まれる。これが将来の最大の参入障壁になる。

| 事業 | 蓄積されるデータ |
|---|---|
| AIR-Plate | 建築設計・施工の業務データ、ユーザー行動データ |
| AIコンサル | AI導入事例、失敗事例、業種別の課題データ |
| BIMプラットフォーム | 業界標準の属性定義、メーカー・仕様書データ |

```
建築業務データ（How） × AI活用知見（Why） × 標準属性定義（What）
= 他社が絶対に持てない「建築AI学習データセット」
```

将来の展開：建築AI SaaSのトレーニングデータ提供・業界レポート販売・起業後の中核資産として活用。

**アクション**

### 提案4：「建築DX道場」人材エコシステム

        ↓
