# 取締役就任構想メモ：梓総研をどう変えるか

> 作成: 2026-06-15  
> 用途: 非公開・自分用の思考整理（取締役就任交渉の前提認識として）

---

## 1. 現状診断：問題の本質

「利益が出ない」は結果であって、原因ではない。
本質は**「稼がなくていい文化が、5年かけて組織に定着してしまった」**ことにある。

### 構造的な問題の連鎖

```
梓設計主宰が方向性を示さない
        │
        ▼
「親会社のイメージアップが自分たちの仕事」という空気が主流になる
        │
        ▼
社長がプレッシャーなくやりたいことを進める
        │（イグジット基準がない・プロジェクトが終わらない）
        ▼
利益を出す議論が封じられる
        │
        ▼
5年目でも独立採算の意識がない
```

### 個別の問題点

**経営層**
- 梓設計主宰：梓総研に言及しない。年1回の発表イベントに参加するが社員とほぼ交流なし。「すごいことをしている」の承認者にとどまっている
- 梓総研社長：細部への気配りはあるが全体像が見えにくい時がある。プレッシャーをかけると潰れるタイプ。やりたいことを主導し、事業のイグジット判断が甘い

**組織文化**
- 「研究すること」と「事業として成立させること」が分離したまま混在している
- 社員が「事業性」を意識するインセンティブがない
- 「好きな研究をする場所」という暗黙の認識が定着している

**梓設計との関係**
- 主宰との接点が「発表会」だけ。日常的なビジネス対話がない
- 梓設計社員にとって梓総研は「よくわからない研究子会社」のまま

---

## 2. 変革の方向性：5つの柱

### 柱1：「稼ぐことを義務にする」文化の宣言

現状、利益を出す議論はタブーに近い空気がある。
取締役として最初にやることは、**「研究してもいい。でも稼ぐことも義務だ」と明言すること**。

- 年度ごとの収益目標を全社員の前で設定・公開する
- 各プロジェクトに「事業貢献度」の評価軸を加える
- 社長の「やりたいこと」と「会社が求めること」を分離して管理する仕組みを作る

**社長との関係設計**
社長を潰さず、変える。石川さんが「利益責任者」として補完する役割分担にする。
社長は「研究の質・対外関係・詳細品質」を担い、石川さんは「事業化・収益・イグジット判断」を担う。これは対立ではなく、社長が本来苦手な領域を補うパートナー関係として提示する。

---

### 柱2：研究と事業を仕分ける

「研究していい」が「何でもやっていい」になっているのが現状。
**全活動を4象限で仕分けし、リソース配分に明確なルールを設ける。**

```
              事業性 高
                  │
  研究性 高  ────┼──── 研究性 低
  （育てる）  　  │      （すぐ刈り取る）
                  │
              事業性 低
```

| 象限 | 分類 | 方針 |
|---|---|---|
| 研究性高×事業性高 | 戦略的育成 | 全体の30%まで。期限と事業化マイルストーンを設定 |
| 研究性低×事業性高 | 主力事業 | 全体の50%。AIR-Plate等。最優先でリソース投入 |
| 研究性高×事業性低 | 様子見 | 全体の15%以内。半年でレビュー・撤退判断 |
| 研究性低×事業性低 | **即撤退** | 継続しない。社長の「やりたいこと」でもここに入れば終了 |

**プロジェクトイグジット基準の明文化**
- 半年でマイルストーン未達 → 自動レビュー
- 1年で事業貢献ゼロ → 原則終了
- 例外は取締役会で審議・承認が必要

---

### 柱3：「好き×社会が求める役割」を社員が認知する

今の社員は「好きなことをやっている」か「言われたことをやっている」かのどちらか。
**自分の強みが社会（市場）でどう役立つかを自覚できる組織にする。**

具体的には：
- 年に1〜2回、個人と組織の「強み×市場ニーズ」をすり合わせる1on1を実施
- 社員が「自分のこの仕事は、誰のどんな問題を解決しているか」を言える状態を目標にする
- それができない仕事・プロジェクトは見直しの対象にする

**人を育てる、とは**
「技術を教える」ではなく、「自分で考えて事業を動かせる人間を作る」こと。
AIが多くの作業を代替する時代に、「AIを使って価値を作れる人」を育てることが最大の育成テーマ。

---

### 柱4：梓設計社員が「数年勤めたい」と思う場所にする

梓総研は今、梓設計の社員にとって「よくわからない子会社」にすぎない。
**梓総研を、梓設計社員のキャリアの選択肢のひとつにする。**

**なぜこれが重要か**
- 梓設計の優秀な社員が2〜3年来ることで、梓総研の実力が上がる
- 梓設計側も「子会社で事業経験を積んだ社員」が戻ることでメリットがある
- 梓設計主宰に「梓総研への関心」を持たせる最も現実的な方法

**実現のための条件**
- 「梓総研で働くと何を学べるか」が明確になっている
- 梓設計と同等以上の待遇（or 成果連動の収入機会）がある
- AIを使った高効率・高付加価値な働き方が体験できる
- 戻った後のキャリアに価値がある（「梓総研経験者」というブランド）

**梓設計主宰との関係再設計**
年1回の発表会から、**四半期に1回の事業報告・対話**へ変える。「すごいことをしているアピール」ではなく、「これだけ稼いだ・これが来期の戦略」を話す場にする。これにより主宰の当事者意識も変わる。

---

### 柱5：「AIが回す20人規模の会社」を実現する

梓設計（大規模）では実現できない。だから梓総研（20人規模）で実現する。
これが**梓総研の存在意義そのものになる**。

**ビジョン：20人で、従来の60人分の仕事をこなす組織**

```
従来の20人規模の会社
  ↓
ルーティン業務・書類作成・分析・レポート → 人間が担う（工数の大半）

AIが回す20人規模の会社（梓総研の目指す姿）
  ↓
ルーティン業務・書類作成・分析・レポート → AIが担う
人間がやること → 意思決定・関係構築・創造・例外処理
  ↓
結果：20人で60人分の売上・付加価値を生み出す
```

**具体的に何を変えるか**

| 業務領域 | 現状 | AI化後 |
|---|---|---|
| 提案書・報告書作成 | 人が書く | AIが下書き、人が確認・判断 |
| 議事録・ナレッジ整理 | 放置 or 人が手動 | 自動記録・自動整理 |
| プロジェクト進捗管理 | 口頭・Excel | AI自動集計・アラート |
| 営業パイプライン管理 | 属人的 | AI予測・優先度付け |
| 請求・契約管理 | 手作業 | 自動化・AI確認 |
| 採用・人事評価 | 感覚的 | データドリブン＋AI補助 |

**梓設計との差別化**
梓総研が「AIが回る会社の実証実験場」になることで、梓設計の大組織が学べないことを先行実装し、梓設計への展開（逆輸入）が生まれる。これが「親会社への貢献」の本来のあり方。

## 3. 変革のシーケンス：誰に・何を・いつ伝えるか

### Phase A（就任前）：実績で「その気にさせる」

- AIR-Plateの売上を上げ、「事業で稼げる」を証明する
- 研究と事業の仕分けを、まず自分の担当範囲で試行する
- 社員1〜2名の意識変革に成功させ、「こういうやり方もある」を見せる

### Phase B（就任交渉時）：明確なビジョンを提示する

- 「自分が取締役になったら、梓総研をこう変える」を1枚で提示
- 梓総研社長には「補完関係」として提示（対立ではなく連携）
- 梓設計主宰には「梓総研が稼げる組織になる」というリターンで語る

### Phase C（就任後）：最初の100日で「文化を変える」

- 収益目標を全社に宣言する
- プロジェクトイグジット基準を明文化・導入する
- 「AI化」の第一弾を1〜2プロセスで実施し、成果を社内発表する
- 梓設計主宰との定期対話を設定する

---

## 4. 自分のポジションの明確化

この変革において、石川さんが占めるポジションは明確にしておく必要がある。

```
梓総研社長：研究の質・対外ブランド・細部品質 を担う
石川さん  ：事業収益・組織変革・AI化・人材育成 を担う
```

これは「社長を否定する」のではなく、「社長が本来苦手な領域を引き受ける」関係。
社長が安心して任せられる存在として振る舞いながら、梓総研全体を事業化の方向へ引き寄せる。

**石川さんにしかできないこと**
- 梓設計AXチーム部長の立場で「現場の実態」を知っている
- AIR-Plateの事業運営を通じて「稼ぐ感覚」を持っている
- AIタスクフォース・芝浦工大WGで「外部との関係」を持っている
- 社長を「潰さず変える」人間関係の構築ができる

---

## 5. 要約：1枚で伝えるなら

**Before（現在の梓総研）**
- 親会社のPR機関として存在している
- 研究＝善、利益＝あまり考えない
- 社員は「好きなことをやる場所」と認識
- 20人規模だが従来型の組織運営

**After（石川さんが変えたい梓総研）**
- 独立採算の事業会社として稼ぐ
- 研究と事業を仕分け、成果にリソースを集中する
- 社員が「事業性」と「自分の役割」を自覚して動く
- 20人でAIを活用し、60人分の価値を生み出す
- 梓設計社員が「数年勤めたい」と思う場所になる
- 梓設計が学べない「AIが回る組織モデル」の実証実験場
